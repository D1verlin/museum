# Руководство по тестированию API в Postman (II этап)

Данная папка содержит готовую коллекцию и переменные окружения для тестирования REST API серверной части интерактивного гида **Национального художественного музея Республики Беларусь (НХМ РБ)**.

---

## Файлы
1. `profmast_api.postman_collection.json` — коллекция запросов Postman v2.1.
2. `profmast.postman_environment.json` — переменные окружения Postman.

---

## Быстрый старт

### Шаг 1. Запуск локального сервера
В корневом каталоге проекта выполните команду:
```bash
npm run server
```
Сервер запустится по адресу: `http://localhost:3017` (на продакшне: `https://museum.diverlin.ru`). При первом запуске автоматически создается и заполняется база данных SQLite (`server/data/museum.sqlite`).

### Шаг 2. Импорт в Postman
1. Откройте приложение **Postman**.
2. Нажмите кнопку **Import** в левом верхнем углу.
3. Перетащите оба файла:
   - `profmast_api.postman_collection.json`
   - `profmast.postman_environment.json`
4. В правом верхнем углу Postman выберите окружение: **«НХМ РБ — Музейный гид (Local Environment)»**.

### Шаг 3. Запуск тестов через Collection Runner
1. Выберите коллекцию `НХМ РБ — REST API`.
2. Нажмите кнопку **Run collection**.
3. Убедитесь, что выбрано окружение `Local Environment`, и нажмите **Run НХМ РБ — REST API**.
4. Все тесты выполнятся последовательно, подтверждая 100% работоспособность API.

## Структура коллекции и проверяемые сценарии

### 01. Аутентификация и безопасность (`/api/auth`)
- **Регистрация посетителя (`POST /auth/register`)**: возвращает `201 Created` и токен JWT. Токен автоматически сохраняется в переменную окружения `{{token}}`. Хеш пароля скрыт.
- **Повторная регистрация (`POST /auth/register`)**: возвращает `409 Conflict` (`EMAIL_ALREADY_REGISTERED`).
- **Вход пользователя (`POST /auth/login`)**: возвращает `200 OK` и валидный токен.
- **Вход администратора (`POST /auth/login`)**: авторизует аккаунт `admin@artmuseum.by`, сохраняет токен в `{{adminToken}}`.
- **Профиль пользователя (`GET /auth/me`)**: возвращает данные пользователя при передаче токена (`200 OK`).
- **Защита эндпоинта без токена**: отклоняется со статусом `401 Unauthorized` (`AUTH_REQUIRED`).

### 02. Залы музея (`/api/halls`)
- **Список всех залов (`GET /halls`)**: возвращает 5 залов с этажами и тематиками.
- **Детали зала (`GET /halls/:id`)**: возвращает зал с вложенными экспонатами.

### 03. Каталог экспонатов (`/api/exhibits`)
- **Каталог (`GET /exhibits`)**: список 15 экспонатов с пагинацией и сортировкой.
- **Фильтрация по залу (`GET /exhibits?hallId=2`)**: фильтр залов.
- **Поиск (`GET /exhibits?search=пояс`)**: полнотекстовый поиск по экспозиции.
- **Детали экспоната (`GET /exhibits/:id`)**: карточка шедевра.
- **Разграничение прав (`POST /exhibits`)**: обычный пользователь получает `403 Forbidden`; администратор получает `201 Created`.
- **Удаление экспоната (`DELETE /exhibits/:id`)**: доступно только администратору (`200 OK`).

### 04. Бизнес-логика хронометража (`/api/routes`)
- **Серверный расчет (`POST /routes/calculate`)**: автоматическое вычисление времени осмотра по темпу, расчет числа переходов между залами (каждый переход = +5 минут) и проверка лимита.
- **Контроль превышения лимита**: выставление флага `isOverLimit: true` и дельты превышения.
- **Кураторские маршруты (`GET /routes/presets`)**: готовые пресеты («Шедевры», «Шляхетское наследие», «XX век»).

### 05. Визиты и цифровые билеты (`/api/visits`)
- **Оформление билета (`POST /visits`)**: серверный перерасчет времени, генерация уникального номера пропуска (`AURA-XXXXXX`), сохранение снимка залов.
- **Валидация санитарного дня (вторник)**: возвращает `422 Unprocessable Entity` (`MUSEUM_CLOSED_TUESDAY`).
- **Валидация часов работы**: попытка записи вне 10:00–18:00 возвращает `422`.
- **Изоляция пользовательских данных (`GET /visits`)**: авторизованный пользователь видит только свои билеты.
- **Поиск по номеру билета (`GET /visits/:ticketNumber`)**: получение пропуска.
- **Отмена визита (`PATCH /visits/:id/status`)**: смена статуса на `cancelled` (`200 OK`).
- **Конечный автомат состояний**: запрет реанимации отмененного билета (`422 INVALID_STATE_TRANSITION`).

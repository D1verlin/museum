# Национальный художественный музей Республики Беларусь — Интерактивный гид

Веб-приложение для составления и расчета персонального маршрута по залам постоянной экспозиции Национального художественного музея Республики Беларусь (г. Минск, ул. Ленина, 20).

---

## Архитектура проекта

Проект состоит из двух связанных частей:
1. **Клиентская часть (Frontend)**: React 19, Vite, Framer Motion, чистый CSS3 с надежной контрастной дизайн-системой, Lucide React (строго без сторонних эмодзи).
2. **Серверная часть (Backend, II этап)**: Node.js, Express.js, SQLite (Sequelize ORM), JWT-аутентификация, bcryptjs, Swagger UI (OpenAPI 3.0), Postman.

---

## Реализованная функциональность II этапа (Серверная часть & Полный путь пользователя)

- **Реляционная база данных SQLite (`server/data/museum.sqlite`)**:
  - `Users` — пользователи системы с хешированием паролей (bcrypt) и ролевой моделью (`user`, `admin`).
  - `Halls` — 5 постоянных экспозиционных залов музея.
  - `Exhibits` — 15 аутентичных шедевров музея с датировками, техниками и временем осмотра.
  - `PresetRoutes` — кураторские маршруты («Шедевры музея», «Шляхетское наследие», «XX век»).
  - `Visits` — оформленные визиты с уникальными цифровыми пропусками (`AURA-XXXXXX`), временем, снапшотом экспонатов и статусами.
- **Интерактивная документация Swagger UI**:
  - Доступна по адресу: `http://localhost:3017/api/docs` (на сервере: `https://museum.diverlin.ru/api/docs`).
  - Спецификация OpenAPI 3.0 с поддержкой Bearer JWT-авторизации, схемами сущностей, валидацией параметров и интерактивным запуском запросов «Try it out».
- **REST API (полный спектр CRUD операций)**:
  - `/api/auth` — регистрация, вход, профиль пользователя (`/me`).
  - `/api/halls` — список и детали залов.
  - `/api/exhibits` — получение каталога с фильтрацией (зал, эпоха, категория), полнотекстовым поиском, пагинацией и CRUD-операциями для администратора.
  - `/api/routes` — серверный расчет параметров маршрута (`/calculate`) и кураторские пресеты.
  - `/api/visits` — строго авторизованное оформление визитов, получение билетов пользователя, смена статуса (`confirmed`, `completed`, `cancelled`), поиск по номеру билета для администратора.
  - `/api/health` — мониторинг состояния API, базы данных и счетчиков сущностей.
- **Серверная бизнес-логика**:
  - **Автоматический хронометраж**: время осмотра экспонатов с учетом темпа (`express` = 0.8, `standard` = 1.0, `inDepth` = 1.3) + время переходов между залами (+5 мин за каждый межзальный переход).
  - **Контроль лимита времени**: определение превышения (`isOverLimit`), расчет дельты и остатка времени на сервере.
  - **Валидация музейных правил**: проверка рабочих часов (10:00–18:00), блокировка бронирования на вторник (санитарный день музея, код `422`), валидация будущих дат.
  - **Автомат переходов состояний визита**: `confirmed` $\rightarrow$ `completed` / `cancelled`. Запрет реанимации отмененных билетов (`422 INVALID_STATE_TRANSITION`).
- **Безопасность и разграничение прав**:
  - Аутентификация по токенам JWT (Bearer).
  - Защита маршрутов оформления: неавторизованные пользователи не могут выпускать пропуски (`401 Unauthorized`).
  - Изоляция данных: обычный пользователь имеет доступ только к своим визитам. Администратор видит все визиты и имеет полные права управления визитами и каталогом.
  - Централизованная обработка ошибок со структурированными JSON-ответами и корректными HTTP-статусами (200, 201, 400, 401, 403, 404, 409, 422, 500).
- **Путь пользователя (UX & UI)**:
  - **Начальное состояние корзины**: маршрут на первом входе строго пустой (0 экспонатов), пользователь формирует его сам либо выбирает кураторский сценарий.
  - **Карточки пресетов**: кнопки выровнены строго в одну строку без переносов.
  - **Авторизация**: лаконичные формы входа и регистрации с контрастными непрозрачными фонами, валидацией и отсутствием демо-кнопок быстрого входа.
  - **Личный кабинет**: просмотр оформленных билетов, модальное окно «Подробнее о маршруте» со списком произведений, залами, хронометражем и функцией печати.
  - **Панель администратора (`AdminView`)**: доступна для пользователей с ролью `admin`, содержит живой поиск по номеру билета `AURA-`, фильтрацию по статусам, перевод в `completed`/`cancelled`, добавление и удаление экспонатов из базы данных музея.
- **Развертывание на VDS Ubuntu (`museum.diverlin.ru`)**:
  - Порт: `3017`.
  - Менеджер процессов: PM2 (`ecosystem.config.cjs`).
  - Веб-сервер: Nginx (`nginx/museum.diverlin.ru.conf`) с SSL-сертификатом Let's Encrypt (Certbot).
  - Подробное руководство: [DEPLOYMENT_VDS_UBUNTU.md](DEPLOYMENT_VDS_UBUNTU.md).

## Быстрый старт

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск серверной части API (порт 3017)
```bash
npm run server
```
Сервер запустится по адресу: `http://localhost:3017`  
- Swagger UI: `http://localhost:3017/api/docs`
- Health check: `http://localhost:3017/api/health`

### 3. Запуск клиентской части (Vite Dev Server)
В отдельном окне терминала:
```bash
npm run dev
```
Клиентское приложение откроется по адресу: `http://localhost:5173` (с настроенным проксированием API-запросов на порт 3017).

### Тестирование в Postman
В каталоге `postman/` подготовлены:
- `profmast_api.postman_collection.json` — коллекция Postman v2.1 (все сущности, бизнес-логика, авторизация, негативные кейсы).
- `profmast.postman_environment.json` — переменные окружения со скриптами автоматического сохранения токенов.
- `README_POSTMAN.md` — пошаговое руководство по импорту и запуску в Postman Runner.
